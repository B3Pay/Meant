A tag gives one position of an interface a meaning. Twelve tags are core: the preregistered eval depends on them, so they are stable within v0. Six are experimental and may change. The tables below are checked against spec §5, the JSON Schema (profile/spec/profile-v0.schema.json, the args_* definitions) and the resolver's applicability checks (checks.mjs). Each tag links to the concept page that explains it.

A tag is one annotation: an address, the tag's name and its arguments. This one is from the ICRC-1 pack:

decimals: { "from": "query:icrc1_decimals" } symbol: { "from": "query:icrc1_symbol" }

Value tags

A value tag sits at a value address (method(i).path, method->(i).path or, in a canister profile, type:Decl.path; see Addresses). opt is transparent: a tag on fee : opt nat applies to the nat. A tag on a type it does not fit is E_TAG_NOT_APPLICABLE; a value tag at a bare method name is E_TAG_TARGET.

Dynamic values

ValueAllowed inRule
{ "from": "query:<method>" } amount.decimals (a number), amount.symbol (text), default.value A query or composite query of the same canister, with no arguments and one result of the expected kind: E_REF_UNRESOLVED, E_REF_NOT_QUERY, E_REF_SHAPE, E_REF_TYPE.
{ "from": "now" }, { "from": "caller" } default.value only Anywhere else is E_DYNAMIC_KIND. now is the canister's clock, never the host's.

Integers that can exceed 253 (amounts, bounds) are decimal strings, such as "100000000". The resolver leaves dynamic values unresolved in the resolved form: resolving them needs the network, so it is the consumer's job (Profile and resolved form).

Whether a default.value literal other than null type-checks against its position. The spec requires consumers to check it before they use a default.

Method tags

A method tag sits at a bare method name. intent and effect may also sit at a case address, an argument address whose last step selects a case of a variant (propose(0).Transfer, D-053); a result address, a type: address or a path through [] is E_TAG_TARGET, and two tagged cases one value can take both are E_CASE_OVERLAP.

irreversible, required: boolean.
replicated, optional: boolean; true only with kind: "read" and irreversible: false on an update method (a read-only update, D-038).
idempotency core an update method (E_IDEMPOTENCY_MODE) mode, required: replay_same_payload.
stamp, required: an argument relpath to the field filled once per intent; it carries a timestamp tag (E_STAMP_UNTAGGED).

default: a class.

Defaults and bounds

RuleSpec
Without an effect tag, a query or composite query is read; an update is write with irreversible: true. The resolved form records these with "origin": "default". §5.3
A query declared as anything but read is E_EFFECT_MODE; a read on an update or oneway method is W_EFFECT_MODE, except the read-only update form. §5.3
A method's effect bounds its cases': when a case effect is transfer, approve, admin or destroy, the method's effect is one of these four, and when a case effect is irreversible, so is the method's (E_CASE_EFFECT). §5.3, D-053
A result case with no class falls back to default (W_OUTCOME_UNCLASSIFIED at info level), and is a warning when there is no default. Consumers treat a case with no class and no default as fail. §5.3
classes may be left out when the result has no variant to select; default is then required and classes every reply. §5.3, D-049
Overlapping outcome keys: the most specific (longest path) wins. §5.3

Tags on an EVM contract

EVM support is spec §15, phase 1: profiles, consent text for calldata and ERC-7730 export. Agent tools, outcome classes over reverts and idempotency by nonce are later phases. See EVM contracts.

An ABI is read as the graph a .did compiles to, so the same tags apply, with these types (spec §15.4):

TagOn an EVM contract
amount uint8…uint256, int8…int256. query: refs are eth_calls of a view or pure function of the same contract with no argument and one result.
timestamp, duration uint32…uint256, int64…int256
bytes bytes, bytes1…bytes32
text string
range an integer type, string, an array
describe, default, ui, intent, effect as on a canister. A template has no [ ] segments (E_TEMPLATE): an ABI value is never absent. effect defaults as in §5.3.
account, subaccount none (E_TAG_NOT_APPLICABLE): an address needs no tag; it is shown with its EIP-55 checksum.
idempotency, outcome, list, names, named not yet (E_TAG_TARGET): they need nonces, receipts and reads that a later phase adds.

The native value a payable function receives has no position yet (open O2, on Open questions).
