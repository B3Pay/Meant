The resolver and the validator report problems as a list of diagnostics; the formatters and the consent generator throw an error that carries a code. Either way, match on the code: the message is written for a person or a model to read. Codes are grouped below by the package that returns them, with the spec's §13 table first. Every code here is copied from spec §13 or from the package's source under profile/packages. 

export interface Diagnostic {
  severity: "error" | "warning" | "info";
  code: string;
  /** A JSON pointer for E_SCHEMA, an address (`send(0).to`, `type:Tokens.e8s`) or a document path (`binds.interface_id`). */
  at: string;
  message: string;
  /** The profile's name, when the diagnostic comes from one. */
  profile?: string;
}

The candid-profile CLI exits with 0 when no diagnostic is an error, 1 when one is (the resolved form is still printed when the service compiles), and 2 for a usage or I/O problem (The candid-profile command).
