Here is one field of the EIP-712 request an x402 payment asks a wallet to sign, and the line of USDC's profile that gives it a meaning: 

"TransferWithAuthorization": [
  // …
  { "name": "value", "type": "uint256" },
  // …
]
decimals: 6 symbol: USDC

The request says the value is a uint256. It does not say that USDC counts in units of 10-6, so that 10000 is 0.01 USDC and 25000000 is 25, that the signature pays to once, or that whoever holds it can submit it. A wallet shows the raw numbers, and an AI agent's key signs whatever it is handed. A profile writes the meaning down once, bound to the contract, and every consumer reads the same answer: the wallet's consent text, and the guard that signs only what fits terms the person confirmed.

An Internet Computer ledger has the same gap. Here is one line of an ICRC-1 ledger's interface, and the line of the ICRC-1 profile pack that gives it a meaning: 

type TransferArg = record {
  // …
  amount : Tokens;
  // …
};
decimals: query:icrc1_decimals symbol: query:icrc1_symbol

The interface says the amount is a nat. It does not say that the ledger counts in units of 10-8, so that "1.5 ICP" is 150000000 and a guess of 6 decimals sends a hundredth of that. It does not say that created_at_time is in nanoseconds and is what makes a retry safe, or that Err.Duplicate means the payment already went through. Agents, wallets and user interfaces each guess, and each guesses differently.

Two layers

interfaces What a call's values are

An EVM contract's ABI and EIP-712 types, read by the resolver, or a .did file, compiled by the meant crate through the official Candid type checker: a validated graph with a content-addressed identity.

 profiles What they mean

A profile attaches tags to positions of that graph: units, intent, effects, retry safety and what each result means.

The interface layer answers "what is this interface?" exactly. A .did file is text: two files can describe the same callable interface with different type names, field order and comments. Compiled, both get the same interface_id, and a change that matters to a caller moves it. The graph also gives every value a position that can be named: icrc1_transfer(0).amount is the amount field of the first argument of icrc1_transfer, whatever the type that holds it is called. The interface layer →

The profile layer answers "what does this call mean?". A profile is a JSON document of annotations, each an address, a tag and its arguments. It binds to an interface_id and never changes it, the way a sidecar describes a file without editing it. A profile can come from the canister's author, from a third party you trust, from a standard pack that matches the interface by subtyping, or from a model that proposes one for a person to approve; the four layers merge per tag and per position. What one profile gives you

Consumers never resolve addresses themselves. @meantjs/profile merges every layer that applies and writes the resolved form: one tree per method, with its tags attached to each position. Everything else reads that.

Where Meant stops

  • It does not call canisters. The packages compile, describe, convert and render; sending a call belongs to the layer above. B3Pay's IC Reactor is that layer for React on the Internet Computer.
  • A profile is a claim, not a proof. An author can describe a drain as "claim reward". Binding to interface_id and provenance on every tag limit the damage; they do not remove it. Security model →
  • EVM first, signing requests before calls. On EVM, profiles of EIP-712 messages, their consent text and the signer's guard are stable within v0; ABI calls and ERC-7730 files are experimental, and agent tools, outcome classes and reconcile exist only for the Internet Computer so far (EVM contracts). Solana is planned and not supported.
  • assumption Typed tools built from profiles reduce the value errors agents make. The preregistered evaluation that would test it is parked (D-066). The profile spec stays a draft, with breaking changes expected before v1, and each one is a decision row and a breaking-change note in the changelog.
