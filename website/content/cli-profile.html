npm install --save-exact @meantjs/profile@0.5.0
npx candid-profile resolve ledger.did --packs > ledger.resolved.json

candid-profile is the command @meantjs/profile installs. It has one command, resolve: it reads an interface, applies the profiles you give it and the packs that match, prints the resolved form on stdout and a summary on stderr. It needs Node 22 or later. Its source is src/cli.mjs, started by bin/candid-profile.mjs.

Usage

npx candid-profile --help
usage: candid-profile resolve  [options] > resolved.json
       candid-profile resolve --envelope  [options] > resolved.json
       candid-profile resolve --abi  [options] > resolved.json

  --envelope    the service's candid-core ContractEnvelope (as `candid-core-cli gen` writes it), instead of
                      compiling a .did here
  --abi         an EVM contract's ABI, a JSON array of human-readable fragments or JSON ABI entries
                      (experimental, spec section 15)
  --profile     a profile to apply (repeatable). A pack given this way must match the service.
  --packs             try every pack in the packs directory; apply those that match
  --packs-dir    packs directory (default: the standard packs this package ships)
  --verbose           also list info diagnostics on stderr
  --quiet             no summary on stderr
  -h, --help          this text

The help text goes to stderr. candid-profile --help, -h, and candid-profile resolve --help print it and exit with status 0; candid-profile with no arguments prints it and exits with status 2.

Inputs

Give exactly one interface:

InputWhat it reads
<service.did>Candid source, compiled with the @candid-core/cli the package pins (0.4.0). One file: an import is not followed, and fails with E_CANDID (did_source_not_found).
--envelope <file>The service's candid-core ContractEnvelope, as candid-core-cli gen writes it beside a generated module. The service is not compiled again, and the resolved form is the same as from the .did (decision D-039).
--abi <file>An EVM contract's ABI: a JSON array of human-readable fragments or JSON ABI entries. Experimental (spec §15).

None of them is a usage error (missing <service.did> (or --envelope <file>, or --abi <file>)), and so is more than one (give only one of <service.did>, --envelope and --abi), or a second positional argument (unexpected argument).

Options

OptionEffect
--profile <file>A profile to apply, read as JSON. Repeat it for several; they merge by layer (Profiles, layers and binding). A pack given this way has to match the service, or it is E_PACK_NOT_MATCHED. Diagnostics name the profile by its name.
--packsTry every pack in the packs directory and apply the ones that match. The others get I_PACK_NOT_MATCHED; a pack for the other kind of interface is skipped silently.
--packs-dir <dir>Where --packs looks: every *.profile.json of kind: "pack" in the directory, sorted by file name. Default: the ICRC-1, ICRC-2, ERC-20 and EIP-2612 packs the package ships (the Permit2, DAI permit, USDC and x402 files beside them are contract profiles, not packs). Without --packs it does nothing. A directory with no pack in it is a usage error.
--verboseList info diagnostics in the summary too. They are always in the resolved form's diagnostics.
--quietPrint no summary. Usage errors are still printed.
-h, --helpPrint the usage text and exit with status 0.

A value option takes the next argument or an inline value: --profile mine.profile.json and --profile=mine.profile.json are the same. A next argument that starts with -- is not taken as a value (--profile needs a value). Options and the input may come in any order. Any other argument that starts with - is unknown option.

Output

stdout holds the resolved form, as JSON indented by two spaces with a final newline, whenever the interface could be read, including when diagnostics hold errors. It is empty when the input does not compile (E_CANDID), the envelope cannot be read (E_ENVELOPE), the ABI cannot be read (E_ABI), or on a usage error. Profile and resolved form describes every field.

stderr holds the summary, unless --quiet:

candid-profile: ledger.did  candid-core:interface:v1:sha256:22eb4787e1a755acb9aabd0ed2121d754098bcd1cedb5d0ed8b5c4effb921846  [26 methods]
  applied     local-ledger     author       candid-profile:v0:sha256:3ab093c4e8583fc5e2efb4e7c8ce595457450bd38c7be6959998c0d17eab3b84
  applied     icrc1            pack         candid-profile:v0:sha256:4eaa9312d60661248ff5627dba9906aa91240abe84cb1b1da8ca20a6fba2e3e6
  applied     icrc2            pack         candid-profile:v0:sha256:f9d75e8bf5ff2edb0b167988feee494eeb54c386e6f62252c4bd96ac56346567
  0 error, 1 warning, 3 info
  warning W_OVERRIDDEN               [icrc1] icrc1_transfer(0).memo  bytes from profile "icrc1" (pack) is overridden by profile "local-ledger" (author) at "icrc1_transfer(0).memo" [icrc1_transfer(0).memo]
  1. The input as you named it, the interface_id, and the number of methods. Absent when the interface could not be read.
  2. One line per profile: its status (applied, rebound, stale, not_matched or invalid), name, origin and profile_id. Applied profiles come first, highest layer first.
  3. The count of errors, warnings and infos.
  4. One line per error and warning, and per info with --verbose: severity, code, the profile it is about in brackets, the address or document path, and the message.

A usage or I/O problem prints candid-profile: and the reason, then the usage text, on stderr.

Exit status

StatusWhen
0No diagnostic is an error. Warnings and infos do not change it. Also --help.
1At least one diagnostic is an error. The resolved form is still on stdout if the interface could be read.
2A usage or I/O problem: no arguments, an unknown command or option, a missing value, a file that cannot be read or is not JSON, a packs directory that cannot be read or holds no pack. Also any unexpected exception.

From code

import { runCli } from "@meantjs/profile";

let resolved = "";
let summary = "";
const code = await runCli(["resolve", "tokens.did", "--profile", "tokens.profile.json"], {
  stdout: { write: (text) => { resolved += text; } },
  stderr: { write: (text) => { summary += text; } },
});
console.log(code, JSON.parse(resolved).interface_id);

runCli(argv, io) is the command as a function: argv starts with the command ("resolve"), io takes the two channels, and it resolves to the exit status, 0, 1 or 2. The help text is exported as USAGE. The functions underneath, without the file handling, are on Validate and resolve profiles.

profile/scripts/validate.mjs is a script in the repository, not part of any published package; run it from profile/ after npm ci. It is a thin wrapper over validateProfile, and it checks one profile at a time: a pack against its own binds.requires (so the interface_id above is the pack fragment's, not a canister's), a canister profile against the .did you give. It never merges layers or searches for packs; that is candid-profile resolve. It reads the schema from the repository's spec/ rather than the copy the package ships.

InvocationDoes
node scripts/validate.mjsEvery packs/*.profile.json.
node scripts/validate.mjs <file>… [--did <service.did>]The files named. --did is the interface for canister profiles; without it a canister profile gets the schema check and W_NO_INTERFACE.
--resolvedPrint the resolved form of exactly one profile. The repository's fixtures/*.resolved.json are generated this way.
--jsonPrint { ok, results }, one result per file with its diagnostics, instead of the report.

It prints PASS or FAIL per file, with its profile_id, its interface_id and every diagnostic, and exits with status 0 when every file passes, 1 when one fails, and 2 on an unexpected exception.
