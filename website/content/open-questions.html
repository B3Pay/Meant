This page mirrors profile/docs/open-questions.md and the open items of the EVM binding, spec §15.8. Ids and owners are as written there. An owner is one of the project's workstreams (W0, W1, …); "Blocks" says what waits on the answer. When a question is answered it moves to the answered list with its date and evidence, and a decision is recorded when the answer changes the spec. Some questions name files of the project's working repository that are not in this public copy (the eval's task review, status logs, proposals).

Open items of the EVM binding

Spec §15.8, for the experimental EVM binding (EVM contracts). These have no owner column in the spec.

ItemStatusQuestion
O1openOverloaded function names (ERC-721 safeTransferFrom). Candidate: name@0x<selector>. Until then an overloaded name is E_ABI.
O2openThe native value of a payable call as a position, with the chain's native decimals and symbol. Until then consent text refuses a payable function.

Assumptions the spec states

Spec §14 lists three assumptions next to its open questions:

  • assumption Typed tools built from these tags reduce agent value errors. This is what the preregistered eval tests.
  • assumption Doc-annotation ergonomics are good enough for authors.
  • assumption Candid subtyping, relaxed for result variants, is the right pack-match rule.
