Nothing in the profile spec covers Solana, and no package reads an Anchor IDL. There is no Solana profile, pack, resolved form or consent text today. This page records what a binding would need, so the gaps are visible; none of it is implemented.

What is decided

The order: EVM first, then Solana. The EVM binding (EVM contracts, experimental) tests whether the split between the interface layer and the profile layer holds on a chain that is not Candid. Solana work starts only after it shows that it does.

What a binding would need

The Solana column below comes from a design proposal, not from the spec. Every entry in it is an assumption to check or an open question; nothing in it is a commitment. The ICP and EVM columns describe what exists, for comparison.

Settling an unknown outcome the ledger's ICRC-3 blocks not yet: receipts are a later phase assumption the status of the transaction's signature
Errors result variant cases, each with an outcome class not yet: outcome classes over reverts are a later phase assumption program error codes
Consent standard ICRC-21 consent text without an envelope, and ERC-7730 files open none found

Each row is a place where the profile layer would have to grow: a new interface reader, a new kind of address, a new source of dynamic values, and new rules for retries and reconciliation. Where the spec stands on each chain today: Internet Computer, EVM contracts and Open questions.
