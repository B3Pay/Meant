What you meant is what runs

Meant is the meaning layer for contract calls and signing requests, EVM first. A profile bound to a contract says what each value means and what each call or signature grants: this uint256 is USDC with 6 decimals, this EIP-712 message pays to once, this permit lets a spender take tokens until a deadline. From one profile come the consent text a wallet shows, a guard in front of an AI agent's signer that signs only what the person agreed to, and ERC-7730 files; on the Internet Computer, agent tools and ICRC-21 consent messages too.

Quickstart · EVM signing What Meant is EVM contracts

From a request to a signature the owner agreed to

Two layers, one job. The interface says what a request's values are; the profile says what they mean.

  1. 01

    Read

    An ABI and its EIP-712 types, or a .did, become one graph with an interface_id.

  2. 02

    Describe

    A profile bound to that id says what each value means and what each call or signature grants.

  3. 03

    Confirm

    The owner confirms a task's terms once, on the wallet's own screen. The model never does.

  4. 04

    Guard

    The key signs only a request a profile reads and whose grant fits those terms.

One x402 payment, start to finish

An AI agent pays an API by x402 on Base Sepolia, a test network. The profile annotations are files in the repository; the terms, the consent text and the verdicts are what the published @meantjs 0.8.0 packages return for this request (Quickstart: EVM signing runs it).

On the Internet Computer: one transfer, start to finish

Where Meant began, and where it goes furthest today: agent tools, outcome classes and reconcile. An ICRC-1 transfer of 1.5 ICP, from the interface to the result. The interface, the annotation and the consent message are real: the first two are files in the repository, and the message is what @meantjs/consent returns for this transfer with the ICRC-1 pack. The JavaScript is compiled against the package's declarations when the site is built.

  1. The interface says what the values are 
    type TransferArg = record {
  from_subaccount : opt Subaccount;
  to : Account;
  amount : Tokens;
  fee : opt Tokens;
  memo : opt blob;
  created_at_time : opt Timestamp
};
// …
icrc1_transfer : (TransferArg) -> (TransferResult);

    The interface says amount : nat. It does not say that the ledger counts in units of 10-8, that created_at_time makes a retry safe, or that Err.Duplicate means the payment already went through. The meant compiler turns the interface into a Contract graph whose identity moves only when the callable interface does; the ICRC-1 standard's fragment has this one:

    candid-core:interface:v1:sha256:7fae0dd330b20f53ae1e4e2cb1947c1c57791da0ae20299ceb499f63228d0689

  2. A profile says what they mean 
    {
  "at": "icrc1_transfer(0).amount",
  "tag": "amount",
  "args": {
    "decimals": {
      "from": "query:icrc1_decimals"
    },
    "symbol": {
      "from": "query:icrc1_symbol"
    }
  }
},

    A profile is a separate document bound to that identity. Each annotation names one position in the interface and attaches a tag to it. This one, from the ICRC-1 pack, says the transfer's amount is a token amount whose decimals and symbol the ledger reports itself. The pack carries 29 such annotations, and applies to any ledger whose interface is a subtype of the standard's.

  3. The agent writes what a person would send_tokens({ to: "ig6pt-…-ig6", amount: "1.5 ICP" }) icrc1_transfer(record { amount = 150_000_000; created_at_time = opt 1_793_059_200_000_000_000; … }) 
    import { parseAmount } from "@meantjs/format";

parseAmount("1.5 ICP", { decimals: 8, symbol: "ICP" }); // "150000000"
parseAmount("1.123456789", { decimals: 8 }); // throws E_EXCESS_PRECISION: never rounded

    An agent writes amounts the way a person does. The tool layer converts them exactly, fills the defaults, stamps created_at_time once per intent and keeps it out of the model's hands, and refuses rather than rounds.

  4. The owner reads what the call does 1.5 ICP ig6pt-bilfj-…-4ysgf-ig6 
    { "FieldsDisplayMessage": {
    "intent": "Send tokens: Send 1.5 ICP to ig6pt-bilfj-ewrb5-gyxsa-gisbm-b7z5p-o47mn-dswdx-s225j-4ysgf-ig6",
    "fields": [
      ["Amount", { "TokenAmount": { "decimals": 8, "amount": "150000000", "symbol": "ICP" } }],
      ["Recipient", { "Text": { "content": "ig6pt-bilfj-ewrb5-gyxsa-gisbm-b7z5p-o47mn-dswdx-s225j-4ysgf-ig6" } }]
    ] } }

    The same profile writes the ICRC-21 consent message for the call, for any method, not only icrc1_transfer. Calls whose effect is transfer, approve, admin or destroy wait for the owner's confirmation, unless a policy the owner set allows them: for a transfer or an approval, that can be terms the owner confirmed for the task. The model never confirms.

  5. Every result has a class
    Result case of icrc1_transferClassWhat the caller does

    Err.Duplicatealready_doneReport the earlier block. Never pay again.
    Err.TemporarilyUnavailableretry_sameResend the same encoded bytes.
    Err.TooOld, Err.CreatedInFutureretry_newStamp again, and ask the person to confirm again.

    Every result case has a class, so the caller knows whether to stop, fix the input, retry with the same bytes, or find out whether the first attempt already went through.

Two layers

interfaces Interface graphs and identities

The meant crate compiles a Candid interface through the official checker into a canonical, validated graph with content-addressed identities. @meantjs/schema gives TypeScript typed schemas, validation and a binary codec from the same graph.

 profiles Profiles: what each value means

The Meant Profile spec, its standard packs for EVM and the Internet Computer, and the five profile packages that resolve profiles and generate consent text, a signer's guard, tools and formatting from them. meant-format does the amount tag in Rust.

What you can build on it

profiles Guard an AI agent's EVM key

The person confirms a task's terms once; the key signs only an EIP-712 request a profile reads and whose grant fits them, x402 and Permit2 included.

 profiles Consent text for a signing request

What an EIP-712 request does, in words and fields a wallet shows, matched by type hash and refused for another chain's or contract's domain.

 profiles Give an agent a canister's tools (ICP)

Input in human units, a preview the person confirms before every send, and retries that cannot pay twice.

 profiles ICRC-21 consent messages for any method

ICRC-21 messages, both forms, from a resolved profile and the encoded arguments, in a browser, in Node, or inside the canister.

 profiles Show and read values exactly

Amounts, times, durations, accounts, subaccounts and bytes, parsed and shown by one rule that refuses excess precision rather than rounding it.

 interfaces Tell whether an interface actually changed

Compare one string. Renamed types, reordered fields and comments leave interface_id where it was; a changed argument type moves it.

 interfaces Encode and decode Candid in TypeScript

A schema-directed implementation of the wire format with no runtime dependencies, which returns issues instead of throwing.

 interfaces Accept .did source you did not write

Every entry point is bounded: over-limit input comes back as a structured diagnostic rather than exhausting memory, CPU or the stack.

 Evaluating it What is actually proven

The verification gates, the cross-implementation evidence, and what is still pending.

The TypeScript on this site is @meantjs/schema 0.6.0 and @meantjs/cli 0.5.1, published on 2026-11-01 and 2026-11-06 under the npm latest dist-tag. CLI 0.5.0, published with that schema, differs only in its source nesting count (Limits and diagnostics). The stable releases before those, @candid-core/schema 0.5.0 and @candid-core/cli 0.4.0, are the code of 0.6.0 and 0.5.0 under the old names: the CLI’s command is candid-core-cli, and the modules it generates differ only in their first two lines, the old header and an import of @candid-core/schema. Migrating from 0.5.0 says what the upgrade means. The stable releases before those, @candid-core/schema 0.4.0 and @candid-core/cli 0.3.0, also type a decoded value as unknown and have no didToDocAttributes; Migrating from 0.4.0 says what that upgrade means. The stable releases before those, @candid-core/schema 0.3.0 and @candid-core/cli 0.2.0, differ more: CLI 0.2.0 declares each type as a $-prefixed local (type $Status = …) and types no method with its mode. Migrating from 0.3.0 says what that upgrade means. The stable releases before those, @candid-core/schema 0.2.0 and @candid-core/cli 0.1.0, have the old surface, and Migrating from 0.2.0 shows what each break means, with before and after code. The old names’ beta dist-tag still names 0.3.0-beta.1 and 0.2.0-beta.1, which lack the changes recorded under 0.3.0 and 0.2.0 and every stable release since.

The crates are meant 0.1.0 and meant-format 0.2.0; the npm packages are @meantjs/schema 0.6.0, @meantjs/cli 0.5.1 and the five profile packages at 0.8.0; the profile spec is Draft 0.2. Any release before 1.0 may change the public API, the serialized shapes, the canonical bytes and every identity computed over them, so pin exact versions: meant = "=0.1.0", npm install --save-exact.
